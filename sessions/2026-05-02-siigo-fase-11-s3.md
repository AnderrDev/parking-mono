Persiste audit row en `siigo_invoice_attempts` siempre (éxito y fracaso) con request/response sanitizados; si la auditoría falla, log a stderr pero no rompe la EF. Network/timeout → throw `SiigoNetworkError`.
- **`auth.ts`** (~110): `getSiigoToken(serviceClient, forceRefresh?) → string`. Lee `siigo_auth_tokens` (id=1); si `expires_at - now() > 5min` retorna cache; si no, hace `POST /auth` con `{username, access_key}` + header `Partner-Id`. Persiste con `expires_at = now() + 23h` (margen vs los 24h que dice Siigo). Audita la llamada `/auth` con `operation='auth'`, sanitizando `access_key` y `access_token` antes del INSERT.
- **`customer.ts`** (~150): `ensureSiigoCustomer(serviceClient, token, baseUrl, customer, invoiceId?) → {siigoCustomerId, created}`. Si `customer.siigo_customer_id` existe → retorna sin llamar Siigo. Si no, `POST /v1/customers` con payload mapeado (`person_type`, `id_type.code`, `name[]`, `fiscal_responsibilities`, `address`, `phones`, `contacts`). En 409 hace fallback `GET /v1/customers?identification=<doc>`. Persiste `customers.siigo_customer_id, siigo_synced_at, siigo_sync_error` en cualquier caso (éxito o fallo). Helpers `mapDocType`, `splitNames`, `mapFiscalResponsibilities` exportados para tests.
- **`mapper.ts`** (~120): `toSiigoInvoicePayload(invoice, customer, payment, items)` arma el JSON con `document.id`, `customer.identification`, `seller`, `items[]` (precio en pesos: `centsToPesos`), `payments[]`, `stamp.send=true`, `mail.send=true`. `mapPaymentMethod(method)` lee env `SIIGO_PAYMENT_*`; lanza error explícito para `'mensual'` (regla Fase 11) y `'error'`. Helper `buildParkingItemDescription(plate, entryAt, exitAt)`. Lectura defensiva de envs con `readIntEnv`.
- **`poll-mapper.ts`** (~50): `mapStampStatus(siigoInvoiceResponse) → SiigoStampInfo`. Mapping `Stamped|Rejected|Sent|InProcess|Pending → SiigoStatusInternal`. ## Decisiones

- **`siigoFetch` no lanza por HTTP error**: deja al caller (EF S4 / S5) decidir qué hacer con cada status. Solo lanza por network/timeout. Esto evita try/catch innecesarios en código que sí espera 4xx (e.g. customer 409 es flujo normal).
- **Auditoría siempre persistida, errores de auditoría no rompen la EF**: el `console.error` deja huella sin escalar. Si auditoría se rompiera y la EF reintentara, podríamos perder facturas. Trade-off: aceptamos que ocasionalmente falte un audit row antes que fallar emisiones.
- **Sanitización recursiva en `sanitizeForAudit`**: case-insensitive sobre `Authorization|access_key|access_token|password`. Aplica también dentro de objetos anidados y arrays. La spec exigía sanitizar headers y body — la implementación los cubre ambos sin requerir que el caller lo haga manualmente.
- **`splitNames`**: si el name no tiene espacio, duplica (`['Juan', 'Juan']`) en lugar de fallar. Siigo Person exige firstName + lastName; valor cosmético. Documentado.
- **`mapFiscalResponsibilities` con allowlist**: solo pasa códigos DIAN que conocemos (`O-13, O-15, O-23, O-47, R-99-PN`). Si el array local está vacío, default `R-99-PN` (no responsable IVA, persona natural). Códigos desconocidos se descartan silenciosamente — opción más segura que mandar valores que Siigo rechace.
- **TTL del token = 23h en lugar de 24h**: margen para evitar usar un token a punto de caducar mid-request.
- **`auth.ts` audita por sí mismo, no via `siigoFetch`**: porque `siigoFetch` requiere un token (chicken-and-egg). Duplica un poco de lógica de audit pero mantiene la separación clara.

## Bloqueos / Pendientes

- **`ensureSiigoCustomer` con `vat_responsible`**: la heurística actual (`true` si responsabilidades incluyen `O-13`/`O-15`) es razonable pero puede no cubrir todos los regímenes. En S8 (QA sandbox) validar que Siigo no rechace por este campo.
- **`mapper.ts` asume un único item por factura**: para Fase 11 está bien — la salida del parqueadero genera una sola línea. Si en el futuro una factura agrupa varias sesiones, hay que extender `items` desde el caller.
- **Helper `centsToPesos` usa `Math.round`**: para totales colombianos (siempre múltiplos de 100), no debería haber redondeo. Lo dejamos como defensa por si una sesión de cortesía con descuento parcial lo necesita.
