================================================================================
CONVENCIONES APLICADAS
================================================================================

NAMING:
  - Archivos: kebab-case.tipo.ts
  - Carpetas: kebab-case/
  - Classes: CamelCase (ParkingSessionEntity, RegisterVehicleEntryUseCase)
  - Interfaces: CamelCase (ParkingSessionModel)
  - Functions: camelCase (plateValidator)
  - Files pattern: entidad/repository/usecase/datasource/etc

PATRONES:
  - Either<L, R> para todas las respuestas (Left = error, Right = éxito)
  - Domain NUNCA importa Data ni Presentation
  - UseCase abstracto con execute() retornando Either
  - Repository abstracto en domain/, implementación en data/
  - DataSource abstract + 2 implementaciones (remote, local)
  - Formularios reactivos centralizados en XxxForms service
  - Componentes dumb (sin lógica de negocio) y smart (orquestan UseCases)

ARQUITECTURA:
  - 3 capas: Presentation → Domain ← Data
  - RLS en BD para seguridad por rol
  - Offline-first con PowerSync
  - Audit log append-only para cambios sensibles
